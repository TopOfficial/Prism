# Prism v1.1 (Acquisition) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the four v1.1 acquisition features from `docs/feature-roadmap.md`: structured Bull/Bear debate UI, Investment Scorecard (shareable PNG), public report pages with SEO, and the Today's Market News homepage.

**Architecture:** The existing single Sonnet call gains a machine-readable `prism-json` appendix (scorecard + condensed debate) that the backend parses out of the report text; report storage schema is unchanged, so old reports keep working. Public pages are server-rendered HTML from FastAPI, proxied onto prisminv.com via Vercel rewrites. Market news is one cached Supabase row per day generated with Haiku.

**Tech Stack:** FastAPI + Supabase (service role) backend on Render; React 18 + Vite + Tailwind on Vercel; Anthropic SDK (Sonnet 4.6 for research, Haiku 4.5 for market news); `markdown` (new Python dep) for server-side report HTML.

## Global Constraints

- No new frontend dependencies (PNG download drawn on a raw `<canvas>`).
- Backend files stay under 500 lines; new endpoints that don't fit `main.py` go in new service modules.
- Old saved reports (no prism-json block) must render exactly as before — `extras` is always optional.
- Ticker path input on public endpoints must be validated (`^[A-Z0-9.\-]{1,12}$`) and HTML-escaped.
- Publishing is only allowed for the caller's own report generated <7 days ago.
- All Supabase DDL is appended to `docs/supabase-setup.sql` as section 6 (user runs it manually).
