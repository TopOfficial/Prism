# Prism v1.4 (Portfolio) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Portfolio analyzer (paste holdings → exposure/risk/valuation + AI assessment) and the merged thesis tracker + journal (record why you bought; get told after each earnings whether the thesis got stronger or weaker).

**Architecture:** One portfolio per user in a `holdings` table; analysis computed server-side from FMP profile/ratios (1h in-process cache per ticker) — the AI narrative is generated from those computed stats only, never invents numbers. Metering: computed analytics for any signed-in user; the AI assessment is subscriber/admin-only (simplification of "3 credits/analysis" — one fewer charging path). Theses live in a `theses` table with a `checkpoints` jsonb log; the v1.2 alert cron evaluates active theses whenever an earnings event fires for that ticker and appends a checkpoint (stronger/weaker/broken/mixed) which also rides the alert email.

**Tech Stack:** existing FMP fetchers, Supabase (SQL section 9), Sonnet for assessment + thesis checkpoints, new PortfolioTab + ThesisCard React components.

## Global Constraints

- Holdings input: plain text/CSV lines `TICKER, shares[, cost_basis]` (comma or whitespace separated). No broker-export auto-detection. Max 50 holdings.
- Portfolio value math is client-visible data (price × shares); weights always sum from included rows only; tickers FMP can't price are returned in an `unpriced` list, never silently dropped.
- Thesis text ≤ 2000 chars, one active thesis per (user, ticker).
- Thesis checkpoints only fire from the earnings path of the alert job (not price moves).
- All new DDL = section 9 of `docs/supabase-setup.sql`.

- `analyze(user_id) -> {holdings: [{ticker,name,sector,price,shares,value,weight_pct,pe,cost_basis,gain_pct}], totals: {value, weighted_pe, top_weight_pct, hhi}, sectors: [{sector, weight_pct}], unpriced: [tickers]}`.

### Task 2: Thesis backend + cron hook
**Files:** create `backend/services/thesis_service.py`; modify `backend/routes/portfolio_routes.py` (thesis routes), `backend/services/alerts_service.py` (earnings hook), `docs/supabase-setup.sql` (9b); test `backend/tests/test_thesis.py`.

- `save_thesis(user_id, ticker, text)`, `get_theses(user_id)`, `delete_thesis(user_id, ticker)`.
