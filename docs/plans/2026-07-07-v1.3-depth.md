# Prism v1.3 (Depth) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Comparable-companies table with real peer data in every Deep Research run, and a per-ticker research chat with memory under each report.

**Architecture:** Peers come from FMP `/stable/stock-peers` (verified working on the current plan) + per-peer `ratios-ttm`, cached in-process 24h per ticker. The backend appends a server-generated ` ```prism-comps``` ` block to the raw report before saving (mirror of the model's `prism-json` block), so saved history and the shared cache carry real peer data without schema changes; `split_report()` strips both blocks on read. Chat stores one `messages` jsonb per (user,ticker); each turn is a Sonnet call with the saved report + trimmed history as context. Free users get 5 turns per ticker; subscribers/admins are capped at 100 messages/ticker as fair use.

**Tech Stack:** existing FMP service patterns, Supabase `research_chats` (SQL section 8), Sonnet 4.6 for chat, React lazy chat box.

## Global Constraints

- Comparables are programmatic data, never model-generated numbers; the model only gets them as context so its prose references real figures.
- Peer metric fetches are shared/cached (24h TTL, in-process) — a research run costs at most 5 extra FMP calls, usually 0 on cache hit.
- Chat context: stripped report markdown + last 20 turns; no external fetches per turn.
- Chat metering server-side: free = 5 user turns/ticker (402 `chat_limit` → subscription upsell), unlimited accounts fair-use 100 messages/ticker (429 `chat_cap`).
- All new DDL = section 8 of `docs/supabase-setup.sql`.
