# Prism v1.2 (Retention) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI watchlist with email alerts that fire only on material changes — earnings released (the "earnings copilot": what changed vs last quarter) and day-over-day price moves ≥5%.

**Architecture:** `watchlists` table keyed (user_id, ticker) with a per-ticker `baseline` jsonb (last price, last seen earnings quarter). A daily cron (Render Cron Job hitting `POST /jobs/run-alerts` with a shared secret) groups watched tickers, detects material events per *distinct ticker* (cost scales with tickers, not users), writes alert text with Haiku (price moves) or Sonnet (earnings deltas), then sends one digest email per affected user via the Resend HTTP API. No Resend SDK — plain requests. Missing RESEND_API_KEY degrades to logging.

**Tech Stack:** FastAPI APIRouter (new `routes/` package so `main.py` stays under control), Supabase, yfinance quotes + existing FMP earnings, Anthropic Haiku/Sonnet, Resend REST API.

## Global Constraints

- Free users: max 3 watched tickers; subscribers/admins unlimited (enforced server-side).
- Alert quality rule: start conservative — ONLY earnings releases and ≥5% day-over-day moves trigger email. No news-sentiment triggers in v1.2.
- Every email includes an unsubscribe link (`GET /unsubscribe?uid=…&token=HMAC(uid, UNSUB_SECRET)`) flipping `users.alerts_enabled=false`, plus a `List-Unsubscribe` header.
- The cron endpoint requires header `X-Cron-Secret: $CRON_SECRET`; without the env var set the endpoint is disabled (403).
- All external failures (quote fetch, model call, email send) skip that ticker/user and continue — the job never dies mid-run.
- New DDL appended to `docs/supabase-setup.sql` as section 7.

## Env vars (new)

`RESEND_API_KEY`, `ALERT_FROM_EMAIL` (e.g. `Prism <alerts@prisminv.com>` — domain must be verified in Resend), `CRON_SECRET`, `UNSUB_SECRET`.

### Task 1: Watchlist storage + CRUD

**Files:** Create `backend/services/watchlist_service.py`, `backend/routes/__init__.py`, `backend/routes/watchlist_routes.py`; modify `backend/main.py` (include router), `docs/supabase-setup.sql` (7a); test `backend/tests/test_watchlist.py`.

**Interfaces:**
- `add_to_watchlist(user_id, ticker, company_name, is_unlimited) -> dict` — raises `WatchlistError("limit_reached")` at 3 tickers for non-unlimited; seeds `baseline` `{price: None, earnings_quarter: None}` (filled by first alert run).
- `remove_from_watchlist(user_id, ticker)`, `list_watchlist(user_id) -> list[{ticker, company_name, added_at}]`.
- Routes: `GET /watchlist`, `POST /watchlist/{ticker}` (body {company_name?}), `DELETE /watchlist/{ticker}` — all auth-required; POST validates ticker with `is_valid_ticker`.

### Task 2: Alert engine + cron + email

**Files:** Create `backend/services/alerts_service.py`; modify `backend/routes/watchlist_routes.py` (job + unsubscribe routes), `docs/supabase-setup.sql` (7b: `users.alerts_enabled`).

**Interfaces:**
- `run_alerts() -> dict` summary `{tickers_checked, events, emails_sent}`:
  1. Load all watchlist rows, group by ticker.
  2. Per distinct ticker: current price (yfinance fast_info, FMP profile fallback) + latest earnings quarter (existing `get_earnings`).
  3. Events vs stored baseline: `price_move` if `abs(pct) >= 5`, `earnings` if quarter key changed. Always update baseline after checking.
  4. Event text: `earnings` → Sonnet ~120 words (uses eps actual/est history); `price_move` → Haiku one-liner. Model failure → template text fallback (never blocks the email).
  5. Group events per user (respect `alerts_enabled`), send digest via `POST https://api.resend.com/emails`.
- `unsub_token(user_id) -> str` (HMAC-SHA256 hex of uid with UNSUB_SECRET), `verify_unsub_token(user_id, token) -> bool` (constant-time).
- Routes: `POST /jobs/run-alerts` (X-Cron-Secret), `GET /unsubscribe?uid&token` → tiny HTML confirmation.
